## 2. 功能需求

### 2.1 参数面板重构（参数直接铺开）

**现状问题**：`KindTab` 把「输出格式/预设/质量/高级参数/输出目录/开始」挤在底部一行，且多数参数藏在可折叠「高级参数」里，不直观。

**目标**：进入工作台后，该类型 TAB 的**常用参数直接平铺展示**，不依赖折叠；按参数分组分区排列；高级/少用参数仍可折叠但默认展开状态可配置。

**实现要求**：
1. 重构 `KindTab` 布局为「顶部：标题 + 状态徽标；中部：文件拖拽区 + 文件列表；下部：**参数面板（平铺）**」。
2. 参数面板按「基础参数 / 高级参数」两块展示，基础参数（输出格式、预设、质量/CRF、输出目录、命名规则、开始转换）**默认全部展开**；高级参数（分辨率/码率/采样率/声道/编码速度等）默认收起，提供「展开/收起」开关。
3. 参数按 kind 动态渲染（沿用现有 `kind === "image/audio/video"` 分支逻辑，抽成可复用渲染函数或小组件 `ParamField`）。
4. 控件统一：间距、对齐、标签与输入间距量化（建议 `gap-3`、`label` 固定宽），长文本截断用 `truncate` + `title`。

### 2.2 预设系统（可保存 / 加载 / 删除 / 重命名）

**现状问题**：`PRESETS`（`ui/src/lib/kinds.ts`）与 `list_presets`（`src-tauri/src/commands.rs`）硬编码 4 项，无法保存用户配置。

**目标**：支持**项目默认预设 + 用户自定义预设**；预设可保存、加载、删除、重命名；**启动自动加载上次使用的预设**；预设记录全部参数 + 目录模式 + 命名规则 + 自定义命令。

**后端（Rust）**：
1. 新增 `crates/infra` 的预设存储模块（或复用 `paths::app_data_dir()` 下的 `presets/*.json`）：一个 `Preset` 结构，字段至少含：
   ```rust
   struct Preset {
       id: String,
       name: String,
       builtin: bool,            // true=项目默认，false=用户自定义
       kind: FormatKind,         // 作用于哪个 TAB，可 null=通用
       options: ConvertOptions,  // target_ext / quality / preset / extra
       out_dir_mode: OutDirMode, // 见 2.4
       out_dir: Option<String>,  // 自定义目录值
       naming: NamingRule,       // 见 2.3
       custom_args: Vec<CustomArgTemplate>, // 见 2.8
       updated_at: DateTime<Utc>,
   }
   enum OutDirMode { ProjectDefault, SourceDir, Custom }
   ```
2. 内置 4 项预设迁移为「项目默认预设」（随版本内置，只读）；用户保存的写 `presets/` 目录 JSON。
3. 新增 Tauri 命令并注册到 `main.rs`：
   - `list_presets(kind: Option<FormatKind>)` → 返回内置 + 用户预设（替代现有硬编码实现）
   - `save_preset(preset: Preset)` / `delete_preset(id)` / `rename_preset(id, name)`
   - `get_active_preset()` / `set_active_preset(id)`（记忆「上次使用」，落盘）
4. 命令桥参数安全：字段名需与前端序列化一致；`options` 复用现有 `ConvertOptions` 序列化。

**前端（React）**：
1. `useAppStore` 新增 `presets` / `activePresetId`，进入应用 `get_active_preset` 自动加载并回填 `KindTab` 全部参数。
2. `KindTab` 预设下拉合并内置 + 用户项；选中即回填参数；「保存为预设」弹窗输入名称 → `save_preset`；「管理预设」入口支持删除/重命名。
3. 参数变更后若偏离当前预设，高亮「未保存」提示；提供「应用预设」「保存预设」「放弃修改」。
4. 删除/重命名前置确认（可复用现有 modal 风格）。

### 2.3 输出命名规则

**现状问题**：输出文件名固定 `unique_output_path` 自动追加序号，用户不可控。

**目标**：独立「命名规则」配置区，支持占位符、前后缀、分隔符，**实时预览**命名效果；命名规则随预设保存。

**占位符**（前端提供插入按钮 + 提示）：
- `{name}` 源文件主名（不含扩展名）
- `{index}` 序号（从 1 起，可设起始值与位数，如 `{index:03}`）
- `{timestamp}` 时间戳（`yyyyMMdd` / `yyyyMMdd_HHmmss`）
- `{originalName}` 完整原名（含扩展名前的全名）
- `{ext}` 输出扩展名（自动追加，不可删）

**规则配置项**：前缀 / 后缀 / 分隔符 / 冲突策略。
**冲突策略**（替换现有固定行为，落到后端）：
- `overwrite` 覆盖
- `skip` 跳过（记录日志）
- `auto_rename` 自动追加序号（现有 `unique_output_path` 行为，作为默认）

**后端**：
1. `crates/core` 新增 `NamingRule`（放 `ConvertOptions` 或 `NewTask`），`crates/converters` 或 `crates/app` 新增 `render_output_name(rule, source, index) -> String` + `resolve_output_path(dir, rule, ...)`，替换 `crates/app/src/lib.rs:221` 的固定 `unique_output_path` 调用。
2. 冲突策略为 `overwrite/skip` 时绕过 `unique_output_path`；`auto_rename` 保留。
3. 规则校验：非法占位符、空结果（如 `{name}` 被删空）返回 `FMT-USER-002 参数无效` 类错误码。

**前端**：命名区提供占位符插入按钮、前后缀输入、冲突策略下拉，下方实时渲染样例（取当前选中首个文件演示）。

### 2.4 目录选择（三模式，绑定预设）

**现状问题**：只有单一输出目录选择（`pickOutDir` + 设置里的默认目录），无模式概念。

**目标**：输出目录提供三种模式，选择结果写入预设：
1. **项目默认**：取「设置-默认输出目录」（`store.defaultOutDir` / 后端配置），未设置时提示去设置。
2. **原文件地址**：输出到源文件所在文件夹（每个文件分别输出到各自所在目录；`TaskItem` 级解析，非整个任务一个目录）。
3. **自定义**：手动选择目标文件夹（现有 `openDialog({ directory: true })`）。

**实现要求**：
1. `KindTab` 用「目录模式」单选（三段切换）替代当前单一按钮；模式为「自定义」时展示当前目录 + 选择按钮。
2. `out_dir_mode` 与 `out_dir` 写入 `Preset`；创建任务时前端把模式转换为 `NewTask.output_dir`（自定义→该目录；项目默认→设置目录；源目录→后端按 item 解析）。**注意**：源文件模式因目录逐文件不同，需在 `NewTask` 增加标记（如 `output_dir_mode`），后端 `crates/app` 对 `SourceDir` 模式逐 `TaskItem` 计算输出目录。
3. 模式切换时保留已填目录值不丢；切换到非自定义时隐藏/禁用目录输入。

### 2.5 设置面板补齐

**现状问题**：`SettingsTab` 仅主题 + 默认输出目录，其余占位。

**目标**：补齐以下设置项，全部可持久化、可重置；按「通用 / 性能 / 转换 / 预览 / 高级」分组展示：
1. 通用：主题（已有）、界面缩放（0.85–1.25 滑杆）、默认启动 TAB、默认输出目录（已有）、语言（暂固定中文）。
2. 性能：**全局任务并发数**（映射 `AppService.max_parallel`，`crates/app/src/lib.rs:36`，新增命令 `set_max_parallel` 或启动时读取配置）、日志等级（tracing `EnvFilter`：off/error/warn/info/debug/trace）、日志保存路径。
3. 转换：默认预设、默认覆盖策略、命令执行超时时间（秒）、错误处理策略（**出错后继续剩余文件 / 终止整个任务**）。
4. 预览：预览缩略图尺寸、预览渲染开关、预览缓存上限。
5. 高级：快捷键（增删改查，见下）、自定义命令目录（见 2.8）、便携模式开关（占位，可先禁用文案）。
6. 快捷键：默认集（开始转换、切换 TAB、打开设置、打开任务列表），支持用户改键；持久化。

**持久化方案**：
1. 新增 `crates/infra` 设置模块，`settings.json` 存于 `paths::app_data_dir()`；启动时加载，改动即写。
2. 新增命令：`get_settings()` / `set_settings(partial: SettingsPatch)` / `reset_settings()`。
3. 前端 `store.ts` 增加 `settings`，打开设置面板时 `get_settings` 拉取、保存时 `set_settings`；「应用」确认生效（或即时生效，二选一，默认「应用后生效」）。
4. 并发数、日志等级等需后端真正读取该配置（调度器初始化时注入），不能只存前端。

### 2.6 UI 布局优化

**现状问题**：`App.tsx` 顶部 TAB + 单列主区，工作台所有内容挤在一个纵向面板，无区域划分、无窗口状态记忆。

**目标**：
1. 工作台分区：**参数配置区（左/上）+ 预览区（右/下）+ 任务列表区（底部可切换）**，各区间用**可拖拽分割线**调整大小（引入轻量分割实现或自定义 pointer 拖拽，不引入大依赖）。
2. **窗口大小/布局记忆**：记录窗口尺寸、当前 TAB、分割比例、折叠状态；下次启动自动恢复（`AppService` 或前端 localStorage 均可，推荐 Rust 端 `settings.json` 存窗口状态，Tauri 启动时 setSize）。
3. 统一控件间距与对齐（建议全局抽 `ParamField` / `Card` 小组件，收敛 `KindTab`/`SettingsTab`/`TasksTab` 里的重复样式）。
4. 窗口缩放适配：容器用 `min-h-0`/`flex` 弹性布局 + 滚动，防止控件溢出与文字截断（现有部分已有 `min-h-0`，需覆盖到所有区域）。
5. 主题切换时 CSS 类切换逻辑保持（`App.tsx` 现有 `dark/light` 切换），补齐缩放/字号响应。

### 2.7 交互响应优化

**现状问题**：无防抖、参数无实时校验、异步无状态反馈、重复点击可能重复提交。

**目标**：
1. **提交防抖**：`开始转换` 按钮在请求期间禁用 + 显示「转换中…」，防止连点重复 `create_task`；文件添加/移除即时刷新。
2. **参数实时校验**：输出格式/目标目录必填（现有部分已校验，补全）；CRF/质量范围、时间戳格式、命名占位符合法性即时提示；非法时禁用提交并高亮字段。
3. **异步状态反馈**：加载预设/设置、拉取任务时显示轻量 loading；操作成功/失败用 toast 或内联提示（不阻塞）。
4. **进度不卡 UI**：任务进度事件已节流（`TasksTab` 现有 300ms 节流），保持；预览加载懒执行，避免主线程卡顿。
5. 空状态文案完善：文件列表为空、任务列表为空、预览为空时给引导提示。

### 2.8 自定义命令参数

**现状问题**：`ConvertOptions.extra` 只承载固定类型参数（图片/音频/视频），无用户自定义命令模板；`list_presets` 无自定义转换器。

**目标**：支持用户**自定义命令参数模板**，绑定界面输入项并做变量注入，保存进预设，命令原始字符串单独落日志。对齐 `前期架构2.md` 的「其他/自定义」TAB 与「用户自定义命令」。

**设计**：
1. `CustomArgTemplate { name, args: Vec<String>, bindings: Vec<Binding> }`，其中 `Binding` 描述界面输入项→变量映射（如 `--crf={crf}`、`{input}`、`{output}`、`{outDir}`）。
2. 工作台新增「自定义命令」区（可放在「其他/自定义」TAB，或在各 TAB 高级区）：编辑参数模板列表、绑定变量、保存到当前预设。
3. 后端：模板在创建任务时展开为真实 `args` 数组，仍走 `Command::new + 参数数组`（**禁止 shell 拼接**）；展开后的完整命令字符串作为日志行写入 `TaskItem.log` / 任务日志（复用 `ctx.note`）。
4. 模板合法性校验：未绑定的变量、空输出路径等报 `FMT-USER-002`。
5. `list_presets` 对自定义命令预设标注来源。

### 2.9 任务列表优化

**现状问题**：`TasksTab` 仅子 TAB 过滤 + 单任务卡片（取消/重试/删除）+ 总进度条，无批量、无暂停/继续、无清空、无 item 级明细。

**目标**：
1. **条目明细**：任务卡片内展示每个文件（`items`）的独立状态/进度/错误，可展开/收起；失败 item 单独重试。
2. **批量操作**：卡片多选（Shift/Ctrl 辅助）、「全选 / 反选 / 清空列表 / 移除已完成 / 移除失败」；批量取消/重试/删除。
3. **暂停 / 继续**：对排队中的任务可暂停/恢复（后端新增 `pause_task` / `resume_task`；运行中任务暂停需「取消后入队待续」，实现时评估可行性，不可行则暂停仅对 queued 生效并注明）。**注意**：需在 `crates/app` 新增命令并注册。
4. **进度与状态**：item 级进度刷新（事件已具备，前端按 item 渲染）；失败标记与错误详情查看（点击展开 `TaskItem.error`/`log`）。
5. 排序：按创建时间倒序；状态徽标颜色统一（排队/进行中/完成/失败/取消）。
6. 保留现有子 TAB 过滤与 300ms 节流刷新逻辑。

### 2.10 预览模块

**现状问题**：后端 `get_preview`（`commands.rs:56`）与 `Converter::preview` 已实现，`api.getPreview`（`api.ts:49`）已定义，但**前端无任何预览组件调用它**。

**目标**：工作台新增预览区（对应 2.6 布局右/下区域）：

## 6. 约束与安全

- 外部进程一律 `Command::new + 参数数组`，禁止 shell 拼接（沿用项目现有 `crates/infra/src/process.rs`）。
- 路径规范化、防目录穿越（沿用现有约定）；输出默认不覆盖原文件。
- 预设/设置 JSON 读写做错误处理，损坏文件回退默认值并记录，不 panic。
- 快捷键不得覆盖系统保留组合；自定义命令模板禁止注入 shell 元字符（按数组传参天然规避）。
- 本期不引入新重型依赖（分割线/预览用轻量实现或现有 lucide/framer-motion 能力）。
