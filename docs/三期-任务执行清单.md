# 格式卷轴 ScrollFormat — 三期迭代·任务执行清单

> 版本：1.0.0 ｜ 依据：《docs/三期规划-界面与体验完善.md》拆解为可执行 WBS
> 适用代码基线：M1 + M2 + 部分 M4（Rust workspace + Tauri 2 + React 19 前端）
> 使用方式：Agent 严格按里程碑顺序执行；每个任务含「涉及文件 / 实施步骤 / 完成标准 / 自测命令」，独立闭环、可单独提交验证。
> 命名约定：后端 Rust 字段用 snake_case（与现有 `NewTask.input_files`、`ConvertOptions.target_ext` 一致，tauri invoke 前后端均用 snake_case）。

## 3. M3-3 命名规则 + 目录三模式（后端 + 前端）

### T3.1 命名规则模型与引擎
- **涉及文件**：`crates/core/src/naming.rs`（新建）、`crates/core/src/lib.rs`（导出）
- **实施**：
```rust
#[derive(Serialize, Deserialize, Clone, Default)]
#[serde(rename_all = "snake_case")]
pub struct NamingRule {
    pub template: String,          // 如 "{name}_{timestamp}"
    pub prefix: String,
    pub suffix: String,
    pub conflict: ConflictPolicy,  // overwrite | skip | auto_rename
    pub index_start: u32,          // 默认 1
    pub index_width: u32,          // 默认 0=不补零
}
#[derive(Serialize, Deserialize, Clone, PartialEq, Default)]
#[serde(rename_all = "snake_case")]
pub enum ConflictPolicy { #[default] AutoRename, Overwrite, Skip }
```
  - 引擎 `render_output_name(rule, source: &Path, index: u32, ext: &str) -> Result<String>`：
    - 支持占位符 `{name}`(主名)、`{index}`/`{index:03}`(补零)、`{timestamp}`(yyyyMMdd 或 yyyyMMdd_HHmmss，规则含 `_HH` 时用带时分)、`{originalName}`、`{ext}`。
    - 结果为空、含非法占位符 → 返回 `AppError::user("命名规则无效")`。
- **完成标准**：占位符替换、补零、时间戳两种格式、非法输入报错均正确。
- **自测**：`cargo test -p scroll_format_core`（补 4-5 个单测：各占位符、补零、空模板、非法占位符）。

### T3.2 输出路径解析与冲突策略落地
- **涉及文件**：`crates/converters/src/lib.rs`（改 `unique_output_path`）、`crates/app/src/lib.rs`（:221 调用点）、`crates/core/src/task.rs`（`NewTask` 加字段）
- **实施**：
  1. `NewTask` 增加 `#[serde(default)] output_dir_mode: OutDirMode` 与 `#[serde(default)] naming: Option<NamingRule>`。
  2. 新增 `resolve_output_path(dir, source, rule, ext) -> Result<PathBuf>`：
     - 无 `rule` 或 `conflict=AutoRename` → 复用现有 `unique_output_path`（保默认行为）。
     - `Overwrite` → 直接 `dir.join(渲染名 + ext)`。
     - `Skip` → 已存在则返回「跳过」标记（不写文件，记日志）。
  3. `crates/app` 处理 `OutDirMode::SourceDir` 时**逐 `TaskItem`** 计算输出目录（`item.input.parent()`），替换统一 `task.output_dir`。
  4. 在 `crates/app` 调度写入 item.output 处（:221-228）接入新解析与模式。
- **完成标准**：三种冲突策略行为正确；SourceDir 模式逐文件各自目录；默认仍 auto_rename 不覆盖。
- **自测**：`cargo check -p scroll_format_app`；手测 Overwrite/Skip/AutoRename 各一次 + SourceDir 多文件。

### T3.3 前端命名规则区 + 目录三模式
- **涉及文件**：`KindTab.tsx`、`ui/src/lib/api.ts`
- **实施**：
  1. 命名规则区（基础参数块内）：占位符插入按钮、前后缀输入、分隔符、冲突策略下拉；下方**实时预览**（取首个选中文件，前端调用 `render_name` 命令或前端实现渲染函数；推荐新增 `render_name(rule, sample)` 命令复用 T3.1 引擎保证一致）。
  2. 目录三模式单选（项目默认/原文件地址/自定义）：自定义时展示目录 + 选择按钮（现有 `openDialog`）；项目默认时读 `settings`；模式与 `out_dir` 写入预设。
  3. `create_task` 透传 `output_dir_mode`、`naming`。
- **完成标准**：命名实时预览与后端一致；三模式切换正确，切换不丢已填目录。
- **自测**：`npm run build`；手测三种模式各转换一次确认输出路径。

## 8. 风险与注意事项

1. **SourceDir 多文件目录**：输出路径从任务级改为 item 级，改动 `crates/app` 调度核心，需先补单测再改逻辑，防止回归既有转换。
2. **运行中任务暂停**：T5.1 的实现成本高于排队暂停；按「取消重入队」实现，避免承诺不实。
3. **命名时间戳两种格式**：`{timestamp}` 不带 `_HH` 用 `yyyyMMdd`，带则用 `yyyyMMdd_HHmmss`；需前后端同一规则，前端预览调用后端 `render_name` 保证一致。
4. **内置预设只读**：`builtin=true` 时禁止删除/改名，UI 置灰。
5. **并发/日志生效位置**：必须后端读取（启动注入 + `set_max_parallel` 运行时改），不能只存前端。
6. **窗口记忆写频率**：resize/move 事件节流（≥500ms）落盘，避免频繁 IO。
7. **预览缓存上限**：默认建议 128 项；按路径做 key，文件变化以 `mtime` 失效。
