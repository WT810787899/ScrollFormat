# ScrollFormat 技术栈说明

## 1. 项目概述

ScrollFormat 是一个面向本地文件转换场景的桌面应用，目标是提供“多格式转换 + 本地优先 + 可持续扩展”的工具链。它采用 Rust 作为核心与桌面应用引擎，前端使用 React + TypeScript 构建界面，借助 Tauri 2 将 Web UI 和本地能力封装成桌面应用。

本项目的核心特点包括：

- 使用 Rust 构建高性能、可靠的转换引擎
- 通过 Tauri 2 打包成桌面应用，保留 Web 交互体验
- 采用分层 Rust Workspace 架构，实现模块解耦和扩展
- 支持 CLI 入口与桌面端双模式运行
- 使用 SQLite 持久化任务状态与配置
- 通过 sidecar / 外部进程机制接入 ffmpeg、ffprobe 等工具

## 2. 总体技术架构

### 2.1 技术选型概览

| 层级 | 技术栈 | 用途 |
| --- | --- | --- |
| 桌面应用壳 | Tauri 2 | 提供 Windows/macOS/Linux 桌面应用能力，连接 Rust 后端和前端界面 |
| 后端核心 | Rust + Tokio | 负责任务调度、文件处理、转换执行、日志与事件处理 |
| 前端界面 | React 19 + TypeScript | 构建交互式 UI，为用户提供任务管理和参数配置界面 |
| 构建工具 | Vite + TypeScript + PostCSS | 前端开发、热更新、构建和打包 |
| 样式系统 | Tailwind CSS | 快速构建统一、现代化 UI 界面 |
| UI 动效 | Framer Motion | 提升交互反馈和界面动画 |
| 状态管理 | Zustand | 管理前端任务状态、配置状态等 |
| 数据存储 | SQLite (rusqlite) | 持久化任务、历史记录、状态恢复 |
| 图像处理 | image crate | PNG/JPEG/GIF/BMP/ICO/TIFF/WebP 等图像转换处理 |
| 多媒体转换 | ffmpeg / ffprobe | 音频与视频转换/分析能力 |
| CLI | clap | 命令行参数解析与脚本化使用 |
| 日志与诊断 | tracing | 应用日志、性能观察和问题排查 |

## 3. 前端技术栈

### 3.1 React + TypeScript

前端位于 ui/ 目录，项目使用：

- React 19
- TypeScript
- Vite
- Tailwind CSS
- Framer Motion
- Zustand
- lucide-react

这套组合适用于：

- 构建现代化桌面端交互界面
- 在 Tauri 上实现高效渲染与交互响应
- 使用 TypeScript 提升代码稳定性和可维护性
- 借助 Vite 进行快速开发和生产构建

### 3.2 UI 设计与状态管理

- Tailwind CSS：用于快速布局、组件样式、响应式 UI
- Framer Motion：用于任务状态、弹窗、切换动画等动效
- Zustand：用于前端全局状态管理，例如任务列表、转换状态和用户配置
- lucide-react：提供统一图标体系，提升 UI 视觉一致性

### 3.3 前端构建能力

ui/package.json 中的脚本如下：

- dev: 启动 Vite 开发服务
- build: 执行 TypeScript 编译和 Vite 构建
- preview: 本地预览构建产物
- tauri: Tauri CLI 调用入口

这意味着前端既可以作为独立 Web 页面开发，也可以直接嵌入桌面应用中。

## 4. 桌面端技术栈

### 4.1 Tauri 2

桌面应用的壳层位于 src-tauri/，采用 Tauri 2 与 Rust 后端配合：

- Web 前端负责 UI
- Rust 后端负责系统访问、任务处理和转换逻辑
- Tauri 提供系统级桥接能力，例如文件选择、窗口管理、事件通信等

Tauri 的优点在于：

- 轻量级桌面应用包体
- Rust 后端提供更强安全性与稳定性
- Web UI 具备较高开发效率
- 与 React 设计模式自然整合

### 4.2 Rust 运行时

项目使用 Rust Workspace，以多个 crate 组织代码：

- crates/core：领域模型、转换抽象、错误类型、注册中心
- crates/infra：数据库、环境探测、进程管理、路径工具封装
- crates/converters：具体转换器，例如图片/音频/视频/占位转换器
- crates/app：应用服务层，任务队列、调度、重试、取消和事件流
- crates/cli：命令行入口
- src-tauri：Tauri 命令桥接层，连接前端与 Rust

这种结构符合 Rust 项目常见的“分层架构”设计，便于后期扩展更多转换器与任务类型。

## 5. 后端核心能力

### 5.1 Rust 生态与异步能力

项目使用了多个关键依赖：

- tokio：异步运行时，处理任务执行与事件循环
- anyhow：统一错误处理
- thiserror：定义结构化错误类型
- tracing：日志记录与诊断
- uuid / chrono：任务 ID 与时间戳管理
- serde / serde_json：数据结构与 JSON 序列化

这些组件构成了项目的基础运行环境，并支撑高并发和任务状态管理。

### 5.2 任务调度与状态持久化

从架构设计来看，项目强调：

- 任务队列
- 取消与重试
- 自动持久化
- 崩溃恢复
- 任务状态跟踪

这部分由 Rust 的 app 与 infra 层实现，数据库使用 SQLite（rusqlite），因此具备：

- 可持久化任务状态
- 断点恢复
- 异常退出后的恢复能力

### 5.3 转换器体系

项目通过统一的 Converter 抽象来实现不同转换器：

- image：图像转换
- audio：音频处理
- video：视频处理
- stub：占位/未实现转换器

转换层还支持：

- 输入/输出格式注册
- 转换器扩展
- 格式校验
- 外部工具调用统一封装

## 6. 数据处理与工具集成

### 6.1 图像处理

使用 image crate 支持多种图片格式，包括：

- PNG
- JPEG
- GIF
- BMP
- ICO
- TIFF
- WebP

这使项目可以在本地完成常见图像转换任务，而不依赖浏览器端离线处理。

### 6.2 音频/视频处理

项目本身通过 sidecar / 外部进程机制接入 ffmpeg、ffprobe 等工具，用于：

- 音频压缩与格式转换
- 视频转码
- 媒体分析
- 场景检查等能力

该设计适合高性能媒体处理场景，也让模块扩展更灵活。

### 6.3 进程封装与环境检测

infra 层中存在：

- ProcessRunner
- 环境探测
- 路径封装
- 外部工具探测

这部分的作用是：

- 判断 ffmpeg / ffprobe / sidecar 等依赖是否可用
- 统一执行外部命令
- 避免 shell 拼接带来的安全问题

## 7. CLI 技术栈

CLI 部分使用：

- clap（命令行参数解析）
- Rust 运行时

例如 README 中的示例命令：

- cargo run -p scrollfmt -- convert in.png -o out.webp

这说明项目不仅具备桌面端能力，也保留了脚本化、自动化处理的入口，适合批处理和集成场景。

## 9. 技术栈优势总结

### 9.1 优势

- Rust 提供高性能、安全性和跨平台能力
- Tauri 让桌面端开发效率更高，不需要引入 Electron 级别的重型架构
- React + TypeScript 让前端交互、状态及组件管理更稳健
- Tailwind 提升 UI 开发速度
- SQLite 提供可靠的任务状态持久化
- 外部工具接入适合多媒体转换扩展

### 9.2 适用场景

该技术栈特别适合：

- 本地文件处理工具
- 批量格式转换应用
- 多媒体加工工具
- 桌面端效率应用
- 需要持久化任务状态和恢复机制的转换平台

“Rust + Tauri 2 + React 19 + TypeScript + Vite + Tailwind + SQLite + ffmpeg/ffprobe + image crate”，
